# Server actions and routes

Anza has no public REST API. The browser talks to the server through **Next.js server actions** (functions in `src/app/actions/`), plus three HTTP routes. This document lists them all.

## 1. Conventions

- **Every action is a public endpoint.** A server action can be called by anyone who can reach the site, with any arguments. Each one must check the session and permissions itself; hiding a button is not security.
- **Start with an access check.**
  - Workspace actions: `requireWorkspace("view" | "comment" | "edit" | "manage")` from `src/lib/workspace`.
  - Project-scoped older actions: `getProjectAccess(projectId, capability)` from `src/lib/workspace-access`.
  - Admin actions: `requireAdminClient()` from `src/lib/admin-guard`.
- **Return a result, do not throw.** The standard shape is `ActionResult<T>`: `{ success: true, ...data }` or `{ success: false, error: "message for the user" }`. Error messages are written for users and never include database or provider details.
- **Validate input.** Ids with `isUuid`, text with `cleanText(value, max)`, URLs with `safeHttpUrl`, stored JSON with `isStorableObject` (256 KB cap), all from `src/lib/validation.ts`.
- **AI calls go through `runAi` / `runAiStructured`** ([AI.md](AI.md)).
- **After a write, call `revalidatePath`** for the pages that show the data.

## 2. HTTP routes

| Route | Method | Purpose |
| --- | --- | --- |
| `/auth/callback` | GET | Completes Google sign-in, email confirmation and password-reset links that carry a `code` |
| `/auth/confirm` | GET | Completes email links that carry a `token_hash` and `type` (work on any device) |
| `/api/health` | GET | Liveness check. `200 {"status":"ok"}` or `503 {"status":"misconfigured"}`. No authentication, no sensitive data |
| `/robots.txt`, `/sitemap.xml` | GET | Generated by `src/app/robots.ts` and `src/app/sitemap.ts` |

Larger files (up to 25 MB) are uploaded by the browser straight to storage: `prepareDocumentUpload` checks permissions and returns the path, then `registerUploadedDocument` verifies the stored file's signature before recording it. Accepted types: PDF, DOCX, XLSX, CSV, TXT, Markdown.

## 4. Pages

| Path | Who | Purpose |

## 5. Keeping this document current

The capability column was written from the code as of version 0.1.0 and summarises the usual case. The source of truth is the first lines of each action. When you add, rename or remove an action, update the table for its module in the same pull request.
